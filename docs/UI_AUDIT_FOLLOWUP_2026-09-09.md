## Reproduced gaps and corrections

The earlier results were rechecked against the original U01/U02 acceptance criteria. The following gaps were reproduced in the previous local build, rather than inferred from source alone.

| Finding | Correction | Verification |
| --- | --- | --- |

Saving uses a stable record ID; if the action commits but draft cleanup fails, the input remains and retry updates that same record. A successful completion starts a fresh action ID. | Browser Help/reload, injected record-write failure, injected cleanup failure, retry without duplication, then a second distinct action. |
| U01: unsaved Home customization reverted after Help and Back. | Widget ordering, visibility, visible registration types, pinned contact and pinned tools share a validated draft. Changes remain separate from applied Home preferences until explicit Save. | Browser changes order, visibility and tools, returns through Help, reloads, verifies the saved preferences have not changed, then saves and reloads successfully. |
| U01: a failed or invalid journey-date edit disappeared after leaving Settings. | Journey-date drafts retain unfinished values, including a future date awaiting correction. Applying a date still rejects future or impossible dates. An explicit Save date control remains available after returning. The field is linked to its description and validation error through ARIA. | Injected settings-write failure, Help/Back, successful retry and reload; future-date draft, validation, correction and persisted applied date. |
| U01: unfinished History corrections disappeared after Help and Back. | A visible correction draft resumes automatically and retains the original source, answers, event time, quick values and optional use details. The five new draft types use strict shared validators during hydration and backup import. Version-3 backup roundtrips preserve their full values, including unfinished dates and correction answers; malformed values reject the import before saved settings can be replaced. No database-version change, dependency change or clinical-content change was needed for this follow-up.
